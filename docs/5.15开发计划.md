# 5.15 开发计划：投放账户巡检与 AI 创建模板

版本日期：2026-05-15  
项目：RoiBang-v2  
范围：投放账户巡检、AI 创建模板，不包含真实执行动作。

## 一、固定边界

这两块开发都必须遵守现有主线：AI 不临场跑业务流程，真实动作只能由固定脚本读取 JSON 配置执行，并输出 JSON 结果。

1. AI 不临场执行真实业务动作。
2. AI 不直接改现有固定创建模板。
3. AI 不猜账户、不猜预算、不猜素材、不猜项目。
4. 真实动作仍然只能走：

```text
JSON 配置 -> 固定脚本 -> JSON 结果
```

5. 账户、项目、单元、素材、预算、出价、ROI 系数，必须来自固定模板、巡检结果、AI 创建模板 JSON，或用户明确输入。
6. AI 创建模板默认不生效，必须人工确认后才允许被创建脚本使用。
7. 固定模板继续保留，不被 AI 覆盖、不被 AI 自动替换。

## 二、模块关系

```text
投放账户数据
  -> run_delivery_patrol.py（投放账户巡检）
  -> delivery_patrol.json（巡检结果）
  -> run_ai_create_template_generate.py（AI 创建模板生成）
  -> ai-template-*.local.json（AI 创建模板草稿）
  -> 人工确认
  -> 创建脚本显式指定模板
  -> 执行结果 JSON
```

系统状态检查，例如 `launchd（macOS 定时任务）`、日志、任务日报，不属于这里的“账户巡检”。它继续保留在定时任务日报里。

## 三、投放账户巡检

目标：把账户、项目、单元、素材当前投放情况整理成稳定 JSON。第一版只做数据整理和状态标记，不输出真实执行动作。

| 项目 | 设计 |
| --- | --- |
| 脚本 | `scripts/run_delivery_patrol.py` |
| 输入配置 | `configs/delivery-patrol.example.json` |
| 输出目录 | `data/runs/delivery_patrol/YYYYMMDDTHHMMSS.json` |
| 第一版数据来源 | 优先读取本地数据库；实时接口查询放到第二阶段，避免第一版过重 |
| 第一版执行动作 | 只读，不关停、不开启、不创建、不调预算、不调出价 |

### 账户维度字段

- 今日消耗
- 昨日消耗
- 近 7 天消耗
- 近 30 天消耗
- 今日转化
- 近 7 天转化
- CPA（转化成本）
- 计费当日付费 ROI（付费回收）
- 启用项目数
- 有消耗项目数

### 项目维度字段

- 项目 ID
- 项目名称
- 项目状态
- 创建时间
- 今日消耗
- 近 7 天消耗
- 近 30 天消耗
- 转化数
- CPA（转化成本）
- 计费当日付费 ROI（付费回收）
- 是否新建项目
- 是否低效项目

### 单元维度字段

- 单元 ID
- 所属项目 ID
- 单元状态
- 今日消耗
- 近 7 天消耗
- 转化数
- CPA（转化成本）
- 使用素材 ID 列表

### 素材维度字段

- `material_id（素材 ID）`
- 素材标题
- `effective_create_date（有效创建日期）`
- 累计消耗
- 近 7 天消耗
- 近 30 天消耗
- 转化数
- CPA（转化成本）
- 是否适合历史放量
- 是否适合近期放量
- 是否适合测新
- 是否适合低转化复测
- 是否适合无转化复测

### 输出结构

```json
  "summary": {
    "account_count": 0,
    "project_count": 0,

  },
  "accounts": [],
  "projects": [],
  "units": [],
  "materials": [],
  "attention_items": [],
  "artifact_path": "..."
}
```

## 四、AI 创建模板

目标：让 AI 基于历史数据和投放巡检结果提出新的创建打法，但不污染现有固定模板。

| 项目 | 设计 |
| --- | --- |
| 脚本 | `scripts/run_ai_create_template_generate.py` |
| 输入 | `delivery_patrol.json`、素材表现汇总、现有固定模板摘要、用户给定目标 |
| 输出目录 | `configs/ai-create-templates/` |
| 输出文件 | `ai-template-YYYYMMDD-NNN.local.json` |
| 默认状态 | `draft（草稿）`，不能自动执行 |

### AI 创建模板可以建议的字段

- 模板名称
- 适用基础模板：7R 通投、7R 男、每付通投、每付男
- 预算
- 出价
- ROI 系数
- 每账户项目数
- 每项目单元数
- 每单元素材数
- 素材回看范围
- 素材筛选规则
- 素材排序规则
- 素材复用规则
- 命名后缀
- 失败处理规则
- 证据说明，例如样本量、命中素材数、历史观察

### 输出示例

```json
{
  "template_type": "ai_create_template",
  "status": "draft",
```

### 禁止行为

- 不自动覆盖历史放量、近期放量、测新、低转化复测、无转化复测。
- 不自动加入日常默认模板。
- 不自动执行真实创建。
- 不根据一句话临场拼参数。
- 不绕过固定创建脚本。

## 五、明天开发顺序

1. 先做 `run_delivery_patrol.py（投放账户巡检）`。
2. 第一版只读取本地数据库，不调用外部接口。
3. 输出第一版 `delivery_patrol.json（投放巡检结果）`。
4. 确认巡检字段是否足够。
5. 再补实时查询能力，例如今日、近 7 天、近 30 天实时消耗。
6. 再做 `run_ai_create_template_generate.py（AI 创建模板生成）`。
7. 先只生成 `draft（草稿）` 模板。
8. 确认后，再让创建脚本支持显式读取 AI 创建模板。

## 六、短期不做

- 不做 Streamlit（网页面板）。
- 不做飞书交互。
- 不做复杂审批包。
- 不做自动执行策略。
- 不做 AI 自动改固定模板。
- 不做 AI 临场调用业务接口。

## 七、最终目标

```text
账户巡检 JSON
-> AI 创建模板 JSON
-> 人工确认
-> 固定创建脚本执行
```

这条链路的作用是把“数据分析”和“真实投放动作”拆开：AI 可以参与分析和模板设计，但真实动作仍然由固定脚本读取明确配置执行。
