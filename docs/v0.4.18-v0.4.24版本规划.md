# v0.4.18-v0.4.24 版本规划

> 版本号已按真实开发顺序更新：`v0.4.17` 已用于“产品自动化定时任务开关”，本规划从 `v0.4.18` 开始。

## 总体主线

后面开发主线调整为：

```text
先修前端基础体验
→ 再打通引力素材表现数据
→ 再优化素材库筛选
→ 再让创建计划自动选素材
→ 最后实现创建时缺素材实时推送
```

核心修正：不做默认全量提前铺货。创建时缺什么素材，再实时推什么素材。

## v0.4.19 引力素材表现数据打通

目的：让素材库真正显示 7 天、30 天消耗和转化。

现在确认的问题：

- 引力报表接口有数据。
- 真实素材 ID 是 `gravity_material_id`。
- 现在代码错误用了 `material_id`。
- 真实请求要按 `album_id` 分页拉，不是按 `material_ids` 拉。
- response 有 `page_info.total_page`，必须分页读取。

业务逻辑：

```text
按产品绑定专辑
→ 调用引力素材报表接口
→ 拉 7 天数据
→ 拉 30 天数据
→ 用 gravity_material_id 匹配本地素材
→ 写入本地表现汇总
→ 页面显示消耗、转化、ROI
```

字段映射：

```text
gravity_material_id → 本地引力素材 ID
AdCost → 消耗
AdShow → 展示
AdClick → 点击
AdConvert → 转化
AppFirstDayPayROI → 首日 ROI
file_md5 → MD5
create_time → 引力创建时间
```

重要边界：

- 没有返回报表的素材显示“暂无表现”。
- 不要写成 0。
- 不下载素材。
- 不上传素材。
- 不创建广告。

重点文件：

- `src/roibang_v2/fetch/gravity_material_library.py`
- `src/roibang_v2/workflows/gravity_material_sync.py`
- `backend/app/services/gravity_materials.py`
- `frontend/src/pages/GravityMaterialsPage.tsx`
- 对应测试

验收：

- 7 天、30 天分别有数据。
- 页面能按消耗、转化、ROI 排序。
- 无数据时显示“暂无表现”。
- 同步结果显示读取页数、入库表现条数、缺失条数。

## v0.4.21 创建计划自动选引力素材

目的：创建计划时不需要手动选素材。

业务逻辑：

```text
选择产品
→ 选择创建模板
→ 系统读取模板里的素材规则
→ 从引力素材库自动筛素材
→ 展示命中素材
→ 展示为什么命中
```

素材规则必须来自配置：

- 时间范围
- 最低消耗
- 最低转化
- ROI 条件
- 素材数量
- 是否新素材
- 是否排除拒审/禁用/缺 MD5

不能做的：

- 前端不能写死投放规则。
- AI 不能猜素材。
- 没有表现数据不能假装满足条件。

页面设计：

```text
创建计划
素材来源：源素材账户 / 引力素材库

命中结果：
符合模板素材 X 个
可直接使用 Y 个
需要实时推送 Z 个
不符合原因 N 条
```

验收：

- 模板规则能解释清楚。
- 选出的素材有中文理由。
- 不符合的素材有中文原因。
- 没有素材时阻断创建。

## v0.4.22 创建时实时推送缺失素材

目的：这是引力素材接入创建计划的关键主链路。

正确业务逻辑：

```text
创建计划选出素材
→ 确定本次目标账户
→ 检查素材是否已在目标账户有媒体素材 ID
→ 已有的直接用
→ 缺失的生成实时推送预览
→ 用户输入“确认执行”
→ 固定脚本推送
→ 查询 task 状态
→ 回填媒体素材 ID
→ 继续生成创建计划
```

为什么不全量提前铺货：

- 一次创建通常最多 200 条素材。
- 只涉及 4-5 个账户。
- 实时推送组合有限。
- 市面系统也多是创建时实时推送。
- 全量铺货几千素材乘几十账户，浪费且风险大。

页面设计：

```text
创建计划预览

素材检查：
已可用素材 X
需要推送素材 Y
目标账户 Z

实时推送预览：
账户名
账户 ID
素材名
引力素材 ID
MD5
推送状态

[输入 确认执行]
[开始推送并继续创建]
```

安全边界：

- AI 不确认执行。
- 页面必须先展示中文预览。
- 真实推送必须固定脚本读取 JSON。
- 推送失败则阻断创建，不继续往下走。

验收：

- 只推本次创建需要的素材。
- 已推过的不重复推。
- 推送失败有中文原因。
- 成功后创建计划能拿到媒体素材 ID。

## v0.4.23 账户库治理增强

目的：明确哪些账户能被系统使用。

业务逻辑：

- 账户来源区分：
  - 人工导入
  - 历史补全
  - 示例
- 账户状态：
  - 启用
  - 暂停
  - 停用
- 只有启用账户能进入创建、项目管理、素材推送。
- 郭靖链路只使用负责人为郭靖的账户。

增强点：

- 支持产品名 / 产品 Key 搜索。
- 支持负责人筛选。
- 支持来源筛选。
- 支持当前筛选结果批量修改。
- 支持粘贴账户 ID 批量修改。

验收：

- 停用账户不会进入任何业务任务。
- 非郭靖账户不会进入郭靖负责链路。
- 批量修改前有预览，执行后有复盘。
- 账户 ID 必须同时显示账户名。

## v0.4.24 业务页任务状态闭环

目的：用户在哪个页面发起任务，就在哪个页面看结果。

业务逻辑：

- 引力素材库发起同步，就在引力素材库看进度。
- 创建计划发起生成，就在创建计划看进度。
- 账户库发起批量修改，就在账户库看结果。
- 任务中心保留，但不强迫用户跳过去查。

页面设计：

```text
当前任务
状态
进度条
中文摘要
失败原因
明细表
原始 JSON 折叠
```

验收：

- 页面内能看到进度和结果。
- 失败原因是中文。
- 有账户 ID 时同时显示账户名。
- 原始 JSON 默认折叠。

## 建议开发顺序

```text
v0.4.18 全站表格体验修复
v0.4.19 引力素材表现数据打通
v0.4.20 本地素材库页面优化
v0.4.21 创建计划自动选引力素材
v0.4.22 创建时实时推送缺失素材
v0.4.23 账户库治理增强
v0.4.24 业务页任务状态闭环
```

一句话总结：

后面不是做“全量提前铺货”，而是先把素材库数据和页面做好，再让创建计划自动选素材，最后在创建时实时推送缺失素材并继续创建。
